# AGENTS.md — Rahala development instructions
## Mission
Build a polished Arabic-first Android geography game described in GAME_DESIGN.md. Owner uses only a browser and Android phone; every build/test must be cloud reproducible. Never require local Android Studio or Flutter installation.
## First task
If repository is not scaffolded, initialize Flutter Android project at root (retain README and design files), application ID com.rahala.geography as a provisional identifier, Arabic app label رحّالة. Use Flutter stable, Dart null safety, Material 3. Pin a compatible Flutter SDK version in CI and document it. Commit pubspec.lock, Gradle wrapper and Android scaffold. Do not commit build outputs, keystores or secrets.
Build the MVP vertical slice in GAME_DESIGN.md, not the full roadmap. Prioritize an installable APK and fun gameplay over breadth. No network requirement, login, ads, Firebase, leaderboard, purchases or backend. Use a simple persistent local store with schema version, atomic/idempotent progress operations and reset confirmation. Choose minimal maintained dependencies; document licenses and sources. Keep code modular, no giant widget or hardcoded repeated quiz content.
## Suggested organization
lib/app/ (theme, navigation, Arabic locale), lib/core/ (models, persistence, validation), lib/features/ (home, chapters, quiz, passport, settings), assets/data/, assets/flags/, assets/fonts/, test/, docs/. Separate pure quiz/progression logic from UI. Inject random source for deterministic tests. Avoid adding unused frameworks.
## Arabic and UI
Set locale ar, Flutter localization delegates and correct RTL direction; native readable Arabic strings. Use bundled appropriately licensed font. Do not mirror flags or maps. Use Arabic labels for semantics, errors, empty states, buttons and progress. Validate at 360dp and with enlarged text. No dead controls, fake images, random facts or copied design. Keep interactions responsive on low-end Android. Support reduced motion and sound toggle; sound must not be required for gameplay. Respect GAME_DESIGN.md visual palette.
## Data
Use verified, licensed, offline sources; record provenance in docs/DATA_SOURCES.md and include attribution/licenses. Validate all records and generated distractors. Keep stable IDs across updates. Handle political/geographic ambiguities per design; exclude unanswerable questions. Never claim complete world coverage until verified. If network access is unavailable in Codex, use sources available in repository or a documented small verified starter dataset; do not silently invent missing content. Defer unavailable modes and assets without dead buttons.
## Cloud CI — mandatory
Create .github/workflows/android.yml with workflow_dispatch and push/pull_request triggers, read-only default permissions, concurrency cancellation and bounded timeout. Use GitHub-hosted Linux, a compatible Java JDK and pinned Flutter SDK; pin third-party actions to reviewed full SHAs where possible. Run flutter pub get, dart format --output=none --set-exit-if-changed ., flutter analyze, flutter test, flutter build apk --debug. Upload build/app/outputs/flutter-apk/app-debug.apk as artifact rahala-debug-apk with actions/upload-artifact and retention 14 days, only after success. Verify wrapper/SDK versions match. Do not upload keys, use release signing, publish to Play or create public releases. Document browser-only artifact download at https://github.com/mrmaftahsa/rahala/actions. If workflow write permissions block push, provide exact file and steps for owner to add via GitHub editor; never claim build success without completed run evidence.
## Testing
Unit tests for quiz question validity, deterministic distractors, scoring, stars, progression, duplicate XP prevention, persistence and mistake review. Widget tests for Arabic RTL home → quiz → result → next level and settings. Test wrong answers and retry, no overflow. Run format/analyze/test/build when tools allow; state exactly what ran and what failed or could not run. Avoid bypassing tests to make CI green.
## Delivery
Work on a dedicated branch and open a PR with summary, screenshots if available, tests and limitations. Do not merge or publish without owner review. Update README with app status, exact CI artifact download procedure, and what is not implemented. Keep changes reviewable. Report actual APK link only when a successful workflow has uploaded it; if CI has not completed, link Actions and label status pending. For further tasks read design and current source before modifying. Never claim background work or fabricate test results.
